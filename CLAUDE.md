# vaokg-site

Личный сайт: интерактивы по IT-книгам (раздел `library`) и игровые симуляторы по рабочему стеку (раздел `simulators`). Делается для себя и узкого круга, не коммерческий проект.

Стек: Vite, React 19, TypeScript, Tailwind, react-router 7. Сборка в `app/`.

---

## Язык

**Нейминг — только английский, без транслитерации.** Имена файлов, компонентов, переменных, типов, маршрутов, идентификаторов в разметке.

**Комментарии в коде — по-русски.** Это осознанное решение: комментарий существует, чтобы владелец проекта читал его с ходу. Комментарий, который приходится переводить, свою работу не выполняет.

**Комментарии описывают правило, а не историю правок:** ни дат правок, ни номеров находок, ни «перенесено откуда». Пометка о сверке — исключение: «сверено на git 2.53.0, 23.09.2026» говорит, откуда взят факт и насколько он свежий, и остаётся.

**Пользовательские строки — в словаре, не в коде.** Ни одна строка, которую видит человек, не пишется прямо в разметке или логике. Образец подхода — `app/src/data/site.ts`: текстовая начинка отдельно, код вёрстки её не трогает.

Склейка строк запрещена: `"Файл " + name + " добавлен"` ломается при переводе, потому что порядок слов в других языках иной. Вместо неё — шаблон с параметром.

**Вывод git-команд не переводится и в словарь не идёт.** `Initialized empty Git repository`, `nothing to commit, working tree clean` и прочее остаются английскими как есть. Настоящий git отвечает по-английски; тренажёр, переводящий его вывод, учил бы неправде.

Английская версия интерфейса сейчас не делается. Требование про словарь существует, чтобы потом она свелась к новому файлу словаря, а не к переписыванию.

## Структура

```
docs/                       материалы, не попадают в сборку
  git-trainer/
    source.html             работающий тренажёр — источник истины по поведению
    spec.md                 спецификация: как работает сейчас
    target.md               целевое поведение — ПРИОРИТЕТ над spec.md и source.html
app/src/
  pages/                    страницы-маршруты, тонкие
  data/site.ts              текстовая начинка сайта
  trainers/<тема>/          тренажёры
    engine/                 логика и тесты, без React
    locales/                словари
BACKLOG.md                  открытые вопросы и хвосты
docs/agent-practices.md     практика работы с агентами
```

Разделы `library` (интерактивы по книгам) и `simulators` (по рабочему стеку) — разные направления. Не смешивать, общих компонентов «на будущее» между ними не делать.

## Границы ролей

Роли описаны в `.claude/agents/`. Три правила, которые нарушаются чаще всего:

**`site-integrator` не правит файлы логики.** Ни одной строки в `engine/`. Если поведение кажется неверным — сказать и остановиться, а не обходить в компоненте и не дублировать правило у себя. Продублированное правило со временем разойдётся с оригиналом, и тренажёр начнёт вести себя по-разному в разных местах.

**`sim-logic` не пишет React, DOM, таймеры браузера и сеть.** Модуль должен запускаться в vitest как есть.

**`reviewer` ничего не исправляет** и не получает ТЗ на реализацию. Он сверяет результат с реальным поведением технологии, а не с замыслом.

И одно разрешение — на общий код:

**Общий код разделов.** Файлы, которыми пользуются несколько разделов (например, `commitFlags.ts`, `optionAbbrev.ts`), править можно, даже если меняется поведение уже готового раздела, — при двух условиях: изменение приближает раздел к настоящему git (сверено прогоном) и закреплено тестом в том разделе, чьё поведение изменилось. Следующий раздел не должен понимать меньше предыдущего.

## Работа

**Не додумывать поведение по памяти.** Если материалов не хватает — остановиться и сказать, чего именно. Додуманное поведение выглядит правдоподобно, проходит беглый просмотр и вылезает потом.

**Не добавлять зависимости без необходимости.** Если задача решается тем, что уже стоит в проекте — решать этим.

**В репозитории — только читающие команды git.** Агенты не выполняют здесь stash, checkout, reset, restore, clean, rebase, commit, push и другие команды, меняющие состояние. Разрешено: status, diff, log, show. Эксперименты с git — только во временном каталоге (mktemp -d). Незакоммиченная работа владельца живёт в рабочем дереве, и откат на полпути её теряет.

**Деплой ручной и делает его владелец проекта.** Агенты на сервер не выкладывают и не трогают веб-сервер, сертификаты, DNS и пароли.

Процедура выкладки и карта сервера — в шпаргалке администратора, вне репозитория.
