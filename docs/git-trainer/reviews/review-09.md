## 1. Одинаковые коммиты в разных ветках склеиваются в один — воспроизвелась

**Где:** `branchRepo.ts`, `branchCommitHash(message, tree, parents)`: хеш считается от родителей, сообщения и файлов.

Сценарий: две ветки от одного коммита, в каждой одна и та же правка с одним сообщением. Между коммитами у git пауза 1,1 с, прогон с `REALTIME=1`.

```
git checkout -b a
EDIT style.css   (h1 → red)
git commit -am "Red h1"
git checkout master
git checkout -b b
EDIT style.css   (h1 → red)
git commit -am "Red h1"
```

Движок:
```
$ git commit -am "Red h1"      (в ветке a)
[a 662ab22] Red h1
$ git commit -am "Red h1"      (в ветке b)
[b 662ab22] Red h1
```
git:
```
[a cd91c43] Red h1
[b f87cf15] Red h1
```

Дальше, продолжение А: `git merge a` на ветке `b`.

Движок (ok=true):
```
Already up to date.
```
git (rc=0):
```
Merge made by the 'ort' strategy.
```
git log у git после этого:
```
*   e7cf46c Merge branch 'a' into b
|\
| * cd91c43 Red h1
* | f87cf15 Red h1
|/
* 3e9a8df Initial commit
```

Продолжение Б, отдельный прогон: `git branch -d a` на ветке `b`, без слияния.

Движок (ok=true):
```
Deleted branch a (was 662ab22).
```
git (rc=1):
```
error: the branch 'a' is not fully merged
hint: If you are sure you want to delete it, run 'git branch -D a'
hint: Disable this message with "git config set advice.forceDeleteBranch false"
```

**Что с миссиями.** На пути А после `git merge a` засчитаны только `createAndSwitch` и `commitAndReturn`. Миссия 5 не засчитана, потому что коммита слияния нет. На пути Б отказа не было, поэтому миссия 6 тоже не засчитана. Слово «блокируются» из сводки точно только для этого пути. Если игрок сделает другие, разные коммиты, обе миссии остаются достижимыми.

**Уточнение, которого в сводке нет.** Тот же сценарий без `REALTIME`, когда у git зафиксированы даты автора и коммитера. Настоящий git тоже получает один хеш на оба коммита, отвечает `Already up to date.` на `git merge a` и удаляет ветку `a` по `git branch -d` без отказа. То есть движок ведёт себя как git в случае, когда автор и время совпадают до секунды. У живого человека время двух коммитов почти всегда разное, и тогда движок расходится с git.

Ссылку на `target.md`, пункт A5, я не перепроверял: это вопрос к эталону, а не прогон.

## 2. В разделе 2 нельзя править, создавать и удалять файлы — воспроизвелась

## 6. Мелочи — все воспроизвелись

### 6.1 `git merge feature --no-ff`: опция названа веткой

После коммита в `feature`, на `master`:

Движок (ok=false):
```
[тренажёр] git merge <несколько веток за раз> — настоящая возможность git, но этот шаг тренажёра её не разбирает. Здесь поддерживается: git merge <одна ветка>.
```
git (rc=0):
```
Merge made by the 'ort' strategy.
 style.css | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
```
Если опция стоит перед веткой, отказ называет её верно:
```
$ git merge --no-ff feature
[тренажёр] git merge --no-ff — настоящая возможность git, но этот шаг тренажёра её не разбирает. Здесь поддерживается: git merge <ветка>.
```
Здесь git отвечает `Already up to date.`, но только потому, что в этом прогоне слияние уже прошло предыдущей командой.

### 6.2 В `git status` нет последней пустой строки при одних застейдженных изменениях

```
EDIT style.css (h1 → red)
$ git add style.css
$ git status
```
Движок:
```
On branch master
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
	modified:   style.css
```
git: то же самое плюс одна пустая строка в конце. Обвязка отрезает у git только один последний перевод строки, и после этого сравнение даёт `[DIFF]`.

### 6.3 Миссия 3 засчитывается при коммите в старой ветке

```
$ git checkout -b feature
$ git checkout master
EDIT style.css (h1 → red)
$ git commit -am "Red h1 on master"
$ git checkout feature
Switched to branch 'feature'
>>> MISSION DONE: commitAndReturn
```
Коммит сделан в `master`, то есть в прежней ветке, а не в новой. Потом игрок перешёл на новую `feature`, и миссия «сделай коммит в новой ветке, вернись на прежнюю» засчиталась. Критерий `commitAndReturn` проверяет только, что текущий коммит — строгий предок коммита какой-то другой ветки, и не смотрит, какая ветка новая.
