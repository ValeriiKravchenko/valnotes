## Граф коммитов и недостижимые коммиты (target.md, часть VI, опасное место 4)

`CommitGraph` берёт `getAllCommits(state)` (все когда-либо созданные коммиты — движок их не
удаляет) и отдельно `getOrphanCommits(state)` (коммиты, не достижимые ни из одной ветки —
чистая функция движка, `undoRepo.ts`). Коммит, чей id входит в `getOrphanCommits`, получает:
- визуально бледный вид (`opacity-40`, вместо обычной непрозрачности — решение вёрстки, не
  движка: сам факт «недостижим» целиком посчитан движком, интерфейс только красит);
- подпись `ui.commitGraph.orphanNote(hash)` — речь тренажёра из словаря («коммит … больше не
  виден ни одной ветке, но не потерян — его можно вернуть по хэшу…»), помеченную 💡, тем же
  визуальным приёмом, что и explanation в терминале — не похоже на вывод git.

Как только на коммит снова указывает ветка (`git branch rescue <хэш>`), он пропадает из
`getOrphanCommits` и рисуется обычным коммитом без подписи — интерфейс тут ничего не запоминает
сам, каждый рендер просто заново спрашивает движок.

Однопородительская цепочка (`UndoCommit.parentId: string | null`, не `parents: string[]`, как у
`BranchCommit` раздела 2) потребовала свою версию `topologicalOrder` — по одному родителю, без
разбора коммитов слияния (в разделе 4 их не бывает, `undoTypes.ts`); саму идею (уровень = высота
в дереве, порядок отрисовки — дело интерфейса) не меняли.

## Как пройти четыре миссии на localhost (`npm run dev`, затем `/simulators/git/undoing`)

Открыв страницу, видно: терминал слева, справа — статус трёх областей, граф коммитов и панель
файлов, снизу — четыре миссии «Что попробовать», все с пустой отметкой «—». Исходная история
(снизу вверх): «Добавить стили» → «сменить шрифт на Comic Sans» → «Добавить структуру страницы»
(HEAD, ветка `master`); сверено с `undoMissions.ts`/`undoCommands.test.ts`, где ровно эти проверки
и используются.

1. **`findComicSans`** («Найди в истории проблемный коммит с Comic Sans», подсказка
   `git log --oneline`). В терминале ввести `git log --oneline` (подойдёт и голый `git log` —
   `undoMissions.ts` засчитывает миссию по любому вызову, начинающемуся с `git log`) и Enter →
   выводятся три строки с короткими хэшами, средняя — «сменить шрифт на Comic Sans». Отмечается
   первая миссия. Запомнить (или скопировать) её короткий хэш — дальше он нужен для revert.

2. **`revertComicSans`** («Безопасно отмени именно этот коммит, не трогая остальную историю»,
   подсказка `git revert <ID>`). Ввести `git revert <хэш-Comic-Sans>` (например, `git revert a1b2c3d`
   — конкретное значение хэша разное при каждой перезагрузке страницы, т.к. это чистая функция от
   содержимого и порядкового номера коммита; подойдёт и `--no-edit`, поведение по revertSuccess
   одинаковое). Вывод — `[master <hash>] Revert "сменить шрифт на Comic Sans"`; на графе коммитов
   появляется новый коммит с этим сообщением сверху, старый коммит остаётся на месте (revert не
   удаляет коммит — target.md, опасное место 1). Отмечается вторая миссия, `style.css` в панели
   файлов и в рабочем дереве больше не содержит Comic Sans.

3. **`resetSoft`** («Для сравнения: git reset --soft HEAD~1 отменит последний коммит, но оставит
   изменения в индексе», подсказка `git reset --soft HEAD~1`). Ввести `git reset --soft HEAD~1` →
   пустой вывод (настоящий git у `--soft` ничего не печатает); на графе коммит-вершина «уезжает»
   на один коммит назад (revert-коммит из шага 2 становится недостижимым — бледнеет, с подписью
   тренажёра «коммит не удалён — его можно вернуть по хэшу»). Панель статуса покажет расхождение:
   индекс всё ещё на уровне «отменённого» коммита, рабочее дерево не тронуто. Отмечается третья
   миссия.

4. **`resetHard`** («А git reset --hard HEAD~1 отменит коммит и перепишет рабочий каталог:
   несохранённые правки пропадут навсегда, а сам коммит останется в git reflog», подсказка
   `git reset --hard HEAD~1`). Ввести `git reset --hard HEAD~1` ещё раз → `HEAD is now at <hash>
   <сообщение>`; ветка, индекс и рабочее дерево совпадают с этим более ранним коммитом, ещё один
   коммит на графе бледнеет с той же подписью тренажёра. Отмечается четвёртая, последняя миссия.

   Дополнительно (не нужно для миссий, но проверяет опасное место 4 и подпись графа целиком):
   `git log --oneline` в этот момент покажет ТОЛЬКО достижимые коммиты — оба «отброшенных» после
   двух reset в п.3–4 в нём не появятся, хотя на графе справа видны бледными. Введя
   `git branch rescue <хэш одного из бледных коммитов>`, можно увидеть, как он снова становится
   обычным (тег ветки `rescue` появляется рядом, подпись тренажёра исчезает) — ровно так, как
   описано в target.md, часть VI, опасное место 4.

Кнопка «↺ Начать раздел заново» сбрасывает состояние и снятые отметки миссий к тому же исходному
seed.
