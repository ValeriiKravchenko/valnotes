## Как пройти обе миссии на localhost (`npm run dev`, затем `/simulators/git/searching`)

Открыв страницу, видно: терминал слева (репозиторий «Проект», три коммита: «Первая версия
renderCard» → «Добавить класс card для карточек» → «Сохранять id товара в data-атрибуте»), справа —
панель файлов с содержимым `app.js`/`utils.js`/`README.md` (текущее состояние — HEAD), снизу — две
миссии шага A, обе с пустой отметкой «—» (третья миссия относится к шагу B и здесь не показывается —
`SEARCH_MISSION_IDS` содержит только `grepDebounce`/`blameDatasetId`, `searchTypes.ts`).

1. **`grepDebounce`** («Найди все упоминания debounce в проекте», подсказка `git grep -n debounce`).
   Ввести `git grep -n debounce` и Enter → две строки: `README.md:4:TODO: добавить тесты для
   debounce.` и `utils.js:5:export function debounce(fn, delay) {`. Отмечается первая миссия
   (движок засчитывает её по факту, что нашлись обе строки, а не по точной форме ввода — подойдут
   и `-i`, `-l`, `-c`, кавычки вокруг шаблона).

2. **`blameDatasetId`** («Выясни, кто и каким коммитом добавил строку
   `el.dataset.id = item.id;`», подсказка «`git blame app.js`, при желании затем `git show <хэш>`»).
   Ввести `git blame app.js` → 7 строк с хэшем, автором, датой и номером; строка 5 —
   `<хэш8> (Марина 2026-04-02 12:00:00 +0300 5)   el.dataset.id = item.id;`. Отмечается вторая
   миссия сразу этим вызовом (второй вариант зачёта — `git blame -s app.js`, затем `git show
   <хэш строки 5>` — тоже работает, показывает `Author: Марина <marina@example.com>`, `Date:
   Thu Apr 2 12:00:00 2026 +0300` и сообщение «Сохранять id товара в data-атрибуте»).

Кнопка «↺ Начать раздел заново» сбрасывает состояние и снятые отметки миссий к тому же исходному
`ru.searching.seed`.

## Замечаний к движку нет

Публичного набора `searchSection.ts` хватило полностью для страницы шага A: `createSearchSection`,
`runSearchCommand`, `getSearchMissions`, `getHeadTree`. (`getCommit`/`getAllCommits` не понадобились
странице — без графа коммитов и без прямого обращения к коммиту по id панели не нужны; они остаются
в публичном API движка для возможного будущего использования, как и было отмечено в
`section6-engine.md`, «Открытые вопросы».) Словарь (`ru.searching`) уже включал весь нужный для
контента раздела текст (errors/explain/missions/seed) — интегратору осталось добавить только `ui` и
одну ссылку в разделе черновика.
