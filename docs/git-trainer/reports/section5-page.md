## Новые файлы

- `app/src/trainers/git/RemoteTrainer.tsx` — компонент раздела 5. Устройство — прямой аналог
  `BranchingTrainer.tsx` (раздел 2): терминал, статус, граф коммитов, файлы с «✎ изменить»/
  «🗑 удалить»/создание, миссии, «↺ начать раздел заново». Пять отличий, все — по заданию и по
  target.md, часть VII:
  - до `git clone` копии нет (`state.local === null`) — панели статуса, графа копии и файлов
    показывают честную заметку («Локальной копии ещё нет — сначала git clone origin local») вместо
    пустых списков, как будто копия уже есть;
  - справа от графа копии — отдельная панель сервера `/team/origin`: её собственный граф коммитов
    и веток (своя объектная база, `getAllServerCommits`) плюс список заметок `state.serverNotes`
    («коллега сделал(а) коммит: …») — оформлены как строки терминала с `#`, а не как вывод git
    (target.md: «терминал сервера «только для чтения» не должен выглядеть как вывод git»);
  - на графе копии коммит, на который указывает `origin/<ветка>` (`state.local.remoteBranches`),
    получает отдельную метку `origin/<ветка>` — рядом с обычными локальными метками веток, но не
    вместо них: это «запись о сервере на момент последнего контакта», а не сам сервер (опасное
    место 1);
  - кнопка «Коллега пушит правку» — в шапке панели сервера, вызывает `colleaguePush` движка с
    текстами `ru.remote.seed.colleague`; после клика новая заметка сразу видна в списке заметок
    той же панели;
  - статус копии показывает upstream как сырой факт (`state.local.upstream[branch]` — есть запись
    или нет), а не вычисление ahead/behind: та классификация — правило git, посчитанное внутри
    `formatRemoteStatus` (`engine/remoteRepo.ts`, внутренний модуль раздела, не переэкспортирован
    через `remoteSection.ts`) — интерфейс её не повторяет, подробности остаются за `git status` в
    терминале (та же граница, что и в `StatusPanel` разделов 2 и 4).

вёрстка обошлась уже написанными функциями плюс прямым чтением публичных полей состояния.

## Как пройти пять миссий на localhost (`npm run dev`, затем `/simulators/git/collaborating`)

Открыв страницу: терминал LOCAL слева (курсор `(—) $` — копии ещё нет), справа — статус копии
(«Локальной копии ещё нет…»), граф копии и панель сервера рядом (у панели сервера уже виден один
коммит «Первый коммит на сервере» с меткой `master`, и кнопка «Коллега пушит правку»), ниже — панель
файлов копии («Локальной копии ещё нет…»), внизу — пять миссий, все с пустой отметкой «—».

1. **`cloneRepo`** («Склонируй серверный репозиторий к себе», подсказка `git clone origin local`).
   В терминале LOCAL ввести `git clone origin local` и Enter → `Cloning into 'local'...`, `done.`.
   Появляется копия: статус, граф копии (коммит сервера с метками `HEAD -> master` и
   `origin/master`) и панель файлов (`README.md`) заполняются. Отмечается первая миссия.

2. **`commitLocally`** («Отредактируй README.md, затем добавь и закоммить изменение локально»,
   подсказка `git add README.md && git commit -m "..."`). В панели файлов нажать «✎ изменить» у
   `README.md` (дописывает фиксированный суффикс), затем в терминале — `git add README.md` и
   `git commit -m "моя правка"`. Вывод коммита — `[master <hash>] моя правка`; на графе копии
   появляется новый коммит поверх исходного, метка `HEAD -> master` переезжает на него (`origin/
   master` остаётся на прежнем коммите — push ещё не делали). Отмечается вторая миссия.

3. **`pushCommit`** («Отправь свой коммит на сервер», подсказка `git push`). Ввести `git push` →
   `To /team/origin` и строка обновления `<a>..<b>  master -> master`. На панели сервера появляется
   тот же коммит с меткой `master`; на графе копии метка `origin/master` догоняет `HEAD`.
   Отмечается третья миссия (push, который что-то отправил, не «Everything up-to-date»).

4. **`commitAfterColleague`** («Нажми «Коллега пушит правку», затем ещё раз отредактируй README.md
   и закоммить локально», подсказка «сначала кнопка «Коллега пушит», потом git add && git
   commit»). Нажать кнопку «Коллега пушит правку» на панели сервера → там появляется коммит
   «Добавить changelog» с `CHANGELOG.md` и заметка «# … коллега сделал(а) коммит: «Добавить
   changelog»»; копия при этом не меняется (`git status` в терминале покажет `up to date` —
   опасное место 1). Затем снова «✎ изменить» у `README.md` в панели файлов копии и в терминале
   `git add README.md && git commit -m "ещё одна правка"`. Отмечается четвёртая миссия (коммит
   именно ПОСЛЕ клика по кнопке).

5. **`rejectPullPush`** («Попробуй запушить — git откажет…», подсказка `git push → git pull
   --no-rebase → git push`). Дальше в терминале:
   - `git push` → отказ: `! [rejected]        master -> master (fetch first)`,
     `error: failed to push some refs to '/team/origin'`, hint-блок про `git fetch` (fetch ещё не
     делали — именно `fetch first`, не `non-fast-forward`, опасное место 2);
   - `git pull --no-rebase` → `From /team/origin`, строка обновления `origin/master`, коммит
     слияния с сообщением по умолчанию `Merge branch 'master' of /team/origin` и
     `Merge made by the 'ort' strategy.` — командой целиком, без отдельного шага «открыть
     редактор сообщения» (в отличие от интерактивного `git merge` раздела 2, здесь это одна
     команда терминала); на графе копии появляется коммит слияния с двумя родителями;
   - `git push` → `To /team/origin`, строка обновления — отправляет и свой коммит, и слияние.
   Отмечается пятая, последняя миссия (цепочка «отклонённый push → успешный pull → push, который
   что-то отправил» — холостые pull/push её не продвигают).

Кнопка «↺ Начать раздел заново» сбрасывает и сервер, и копию, и все пять отметок миссий к тому же
исходному seed (один коммит на сервере, копии ещё нет).
